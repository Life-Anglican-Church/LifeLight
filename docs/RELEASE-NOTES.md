# LifeAC Lighting 0.6.0 — Colour desk, 11am mute groups and scene recovery

Close Lighting from the tray, then run the updater or installer. Update control-only PCs as well as the host. Shows, accounts, fixtures, groups, photo positions, MIDI mappings and installation roles are retained. This is a Windows release.

## Light controls and layout
- Every configured light has a 0–100% Dimmer. Dedicated dimmer channels are used when available; colour/white-only fixtures use a software dimmer across their known emitter channels. Hue is retained through black. Motion, shutter and protected/function channels are excluded from the software dimmer.
- Individual colour-channel sliders are replaced by a hexagonal colour palette. Pick hue/saturation by click/drag, use the colour swatches, or use the keyboard (left/right hue, up/down saturation, Home white, End full saturation). Automatic white uses the fixture's white emitter when available. Dimmer remains separate. Colour selection changes only known RGB/white/amber channels and retains the current brightness of colour-only lights. White-only fixtures show Dimmer rather than an inapplicable colour picker.
- Eight custom colour slots are shared by the host. In Admin mode, right-click a slot to save the current colour; click to recall it. Colours are retained after restarting. The same palette is available in live controls, the scene editor, fixture controls and the placement/identification configurator.
- Scenes remain on the left, with a large uncropped stage photo on the right. Selected-light controls occupy a panel across the bottom, roughly a quarter of the window. The photo fits above it, including on 1280×720 screens. Fixtures/groups, Save, Release and right-click scene actions remain available.
- Reference reviewed: [Chromateq's ProDMX 2 scene interface](https://filedownload.chromateq.com/Manuals/pro2/en/How%20to%20Use%20scenes.pdf), [fixture selection and bottom presets](https://filedownload.chromateq.com/Manuals/pro2/en/How%20to%20manage%20lighting%20fixtures.pdf), and [the documented colour palette/preset workflow](https://filedownload.chromateq.com/Manuals/player/en/How%20to%20Patch%20Profiles.pdf). The hexagonal visual is an original implementation of that workflow.

## 11am is now a fixture mute
- The old global 75% brightness reduction is removed.
- In Admin mode, right-click 11am, or use Settings > 11am mute group. Choose lights on the photo or from the list and save. The initial mute list is empty so the app does not guess which lights should go dark.
- Clicking 11am mutes those selected lights completely. Other lights retain their normal values. Scene calls, MIDI, timing and effects continue normally underneath; turning 11am off restores the currently commanded look.
- Mute is the final output layer, so manual faders, previews and scene changes cannot relight a muted fixture. It zeros known dimmer/emitter channels while preserving motion and function channels and keeping the DMX connection active. It does not stop the whole DMX universe or zero moving-head position/reset channels.
- The chosen membership is saved on the host. Normal host shutdown resets the active mute toggle. Scene Save captures the underlying unmuted configuration, so a temporary 11am mute is not baked into scenes.

## Scene stability and diagnostics
- USB reconnection resumes the same held scene, current step, fade, effect phase, manual holds and mute state. It no longer re-arms the scene from its beginning. Playback timing pauses while USB is unavailable.
- A failed first open retains the explicitly selected scene for retry. An unavailable held/selected scene causes a reported error rather than silently choosing a different fallback.
- Automatic USB takeover/recovery shares the same command queue as operator connections. A slow manual open cannot race another open or a background probe. The queued attempt rechecks the current state before touching USB.
- Callbacks and pending requests belonging to an old USB helper cannot fault or overwrite a replacement connection.
- The host atomically checkpoints playback progress. A compatible show/patch can recover its previous playback after a host restart instead of starting a default scene. Unexpected restart within the same Windows boot can recover manual holds and mute; a clean tray/Windows shutdown clears these temporary holds. Changed patch revisions are excluded from raw-frame recovery. Checkpoints are host commands, not fixture telemetry.
- Host snapshots have increasing sequence numbers. Old HTTP responses cannot overwrite a newer MIDI/host event in the client. Scene selection no longer appears to roll back because of response ordering. Startup checks verify that the login screen stays hidden and live host events arrive.
- Diagnostics record scene transitions, the resulting scene after client commands, MIDI cue details and USB resume decisions. No recent report of the user's intermittent Centre Focus change was available during development, so its exact historical trigger is not confirmed. The concrete reset/race paths above are fixed and tested; a new on-site log can distinguish an actual cue from a connection/restart event.

## Validation
41 automated engine/server/security/protocol tests pass, including palette channel mapping, selected emitter mute with 16-bit dimmers, paused playback recovery, failed-open scene retention, checkpoint restoration, old-helper callback isolation, ordered snapshots and persistent mute/preset settings. Two Windows desktop browser flows check existing editing/group/save functionality plus pointer/keyboard colours, white mixing, presets, multi-model brightness, mute across scene calls and release, live startup events, and non-overlapping photo/panel layouts at 1280/1440/1920 widths. The real hidden Electron client starts and exits while its simulation host continues. Native helpers compile. Installer payload, source files and release hashes are checked without running the installer. No physical USB, native MIDI input or ProDMX was opened on the laptop.

Host MIDI/LAN and physical light response still require on-site verification. Standalone memory writing remains unfinished and disabled; this release does not change that capability.
