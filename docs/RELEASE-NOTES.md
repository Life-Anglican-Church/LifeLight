# LifeAC Lighting 0.4.0 — Windows dashboard, automatic MIDI and host roles

Close Lighting from its tray menu, then update. To choose a PC role, run the new installer: Control another PC (laptop) or Host USB/MIDI (main/backup PC). New installs default to control-only; existing host installs keep their role. The new updater preserves the selected role. Existing shows, users, MIDI mappings and pin positions are retained.

## MIDI diagnosis and correction
The supplied lighting.jsonl shows MIDI remained disconnected throughout the run. There was no saved MIDI input and no midiStart operation, although a scene note mapping was saved. The source dropdown listed ports without opening one until a separate button was pressed.

The host now starts MIDI listening automatically. It selects the saved port, otherwise the sole loopMIDI port or sole input; multiple ambiguous inputs require one selection in Settings. Selection immediately saves and opens the input. It reconnects when a port disappears or changes device index. A failed background device-list check now leaves an already-open listener processing notes; it cannot latch MIDI into a disconnected state. Windows port-close notifications also trigger reconnection. MIDI remains in the host with no client windows connected. A mapped MIDI cue can end a live scene preview and play its scene; the unsaved draft stays in the editing window and must reacquire preview before saving. Manual fixture overrides remain held. Prior disabled settings no longer prevent startup listening, as requested. Opening errors are retained and the host logs every received note and why it did or did not trigger a scene. The compiled Windows helper's actual packed-message decoder and process pipe are tested through to scene activation without any clients; this is not a physical loopMIDI test on the projector PC.

## Main screen
- Four-column scene grid on normal desktop widths, with the stage photo and selected-light controls on the right. Windows desktop only; no mobile release is being built.
- Left-click a scene to run it. Right-click for Run, Edit, MIDI trigger, Folder, Duplicate and Delete (editing controls require Admin). Admins drag the six-dot handle to reorder scenes. There are no per-card control buttons or ordering arrows.
- Select multiple fixture pins to control their shared settings. A single light shows its supported safe controls. Mixed 8/16-bit shared controls use percentages. Unverified reset/function channels remain protected.
- Scene editing also supports multiple pins and shared faders. Click the photo background or surrounding editor space to deselect. Editing and manual-control handlers are scoped separately, so live scene previews cannot overwrite the main controls' handlers.
- A small Manual indicator replaces the large override banner. Its menu releases individual lights or all overrides, or saves them to a scene. Release all lights returns fixtures to the current scene and keeps USB control. Disconnect controller ends USB control.
- Separate MIDI and DMX indicators show their own status in the top corner. MIDI indicates recent activity, received-message counts and scene-match decisions. Loss of the host connection marks device state unknown.

## Settings and installation
- Settings is a popup containing MIDI and scene triggers, lights/profiles, LAN/accounts, takeover options, show import/export and diagnostics.
- Stage placement appears only under Settings > Arrange stage photo. That configurator includes live controls to identify each light before placing its pin, plus release-selected controls. Main-screen pin selection never repositions lights.
- Control-only installations omit Node, engine/server files, USB/MIDI helpers and the standalone worker. They connect to a host over HTTPS. Host installations retain the tray-supervised USB/MIDI engine and standby-controller detection. No Windows autostart entry, driver replacement or Windows system service is installed.

## Standalone investigation
The supplied standalone report reads firmware 2.4.2.3, model-layout 7, two available universes, and configuration reporting 35 scenes and 320 used channels on output A. It stopped at command 0x71, scene 4, step 18; completeMemoryBackup is false. The reader incorrectly used header bytes 2-3 (scene fade ticks) as the step count. ProDMX uses bytes 9-10 for step count; the supplied headers contain 25 fade ticks (1 second) and 1 actual step. That decoder error caused reads to spill into neighbouring scenes. It is fixed and covered by a regression using the actual header. The old report remains unsuitable as a restoration image, and corrected full-device reading still needs the on-site run.

Settings > Standalone controller now runs the isolated read-only worker on the host and exports its report. Live output must first be disconnected. Automatic takeover stays suspended until deliberately reconnected; the worker checks SDK/firmware fingerprints and repeats reads, retries rejected read commands, retains partial data and cleans up on host cancellation. No memory write or erase command is exposed. **Standalone writing remains unfinished and disabled** because the complete backup and write/restore procedure have not been verified. The imported PC button plan is labelled separately from device reads.
