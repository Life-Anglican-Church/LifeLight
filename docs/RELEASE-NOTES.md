# LifeAC Lighting 0.3.0 — independent host and live editing

Close the previous app from its tray menu, then run the updater. Existing shows, accounts, scene mappings and backups are preserved. No Windows startup entry, driver replacement or system service installation is added.

- USB, MIDI and scene timing now run in a separate host process supervised by the tray launcher. Every desktop window connects to that host. Closing or losing the client does not close USB. A crashed host is restarted with a delay.
- The tray can switch a computer into remote-client mode: enter the lighting PC's HTTPS address and sign in using a host account. Remote mode starts no local lighting host. The host's own client authenticates automatically and still starts in Volunteer mode.
- USB acquisition runs while the tray host is running, including with no clients. Default first scene is Full Stage; Settings changes the scene or disables automatic takeover. Cable faults retry using the last accepted outgoing frame. A deliberate Release suspends retries. Multiple USB controllers are rejected rather than guessed. This does not operate a physical USB switch or synchronize separate PCs' show files. Use Settings > Export show / Import show to keep a standby PC current before switching USB.
- USB communication tolerates isolated frame rejections and waits longer for slow SDK replies. Repeated rejection or timeout becomes a logged fault and reconnection attempt. The reported recurring hardware dropout has not been reproduced on hardware here; this release provides recovery and evidence to diagnose it.
- Automatic, rotating diagnostic files record actions, USB worker events, health counters, errors and MIDI messages/scene triggers. Settings > Export diagnostics includes the retained log. Passwords, PINs and access tokens are not recorded. Logs remain on the host until shared manually.
- MIDI connection status now waits for confirmation that Windows opened and started the input. The callback queues messages for processing outside the driver callback; received notes are flushed promptly. Source selection reconnects on the host. Note-off/zero-velocity notes never launch a scene. A matching note replaces the active scene with its configured fade; old effects/sequence stop and unselected brightness channels fade out while unselected positions are held.
- Shared control: every window sees the same scene; the latest scene selection wins. Live editing reserves the preview for one window, shown to all users. Another operator can explicitly end the preview and play a scene. Stale preview writes are rejected; an abandoned preview expires after 45 seconds. Saves still require the current show revision. Show data is sent only when it changes, rather than repeatedly with every status update.
- Edit selects the scene and enables live faders automatically. Step selection also previews immediately. Save retains the saved scene live; Cancel restores its original selection.
- Existing fixture names are copied into a separate Model field and retained as Name, ready for location-based renaming. Name/model/group changes are allowed while connected; address changes still require release.
- Both supplied experimental standalone reports successfully read 128 configuration bytes from firmware 2.4.2.3. Full scene readback and standalone writes are still unfinished and remain disabled.

Validated with simulation-only engine/server/security tests, native helper compilation, desktop/mobile browser flows with live faders, and the real Electron client opening then exiting while an independent simulation host continues. No USB, native MIDI or ProDMX was opened on the development laptop. Physical controller stability, actual MIDI delivery and two-PC USB switching still require on-site verification.

The MIDI callback change follows [Microsoft's MIDI callback documentation](https://learn.microsoft.com/en-us/previous-versions/dd798460(v=vs.85)).
